### P0 — fixed
- **AND-01** `ui/playlists/PlaylistsScreens.kt` — **Compile error**: AI-playlist dialog dismiss called `load()` but the loader is `suspend fun load(expectedGen: Int)`. Now `scope.launch { loadGen++; load(loadGen) }`.
- **AND-02** `media/NowPlayingNotificationManager.kt` — **ANR risk**: notification `sync()` ran `runBlocking { HTTP }` artwork fetch on the main looper. Build + artwork fetch moved to a single-thread background executor; state snapshotted on the calling thread.

- **AND-03 / AND-15** `MainActivity.kt` — failed `testConnection()` fell through to `hasServer = app.hasServerUrl()`, entering the main UI with a dead server (the old `runCatching` also always hit `onSuccess` because `testConnection()` returns a `Result`). - **AND-05** `ApiDtos.kt` + `NowPlayingScreen.kt` — server sends `shuffle` per device on `/api/nowplaying_devices` but the DTO lacked the field; shuffle toggle never seeded. Added `shuffle: Boolean` and seeding (preserving pending local toggles).
- **ANEW-01** `ApiDtos.kt` — smart playlist link: DTO field `playlistId` vs server's `linkedPlaylistId` → always null. Fixed with `@SerialName("linkedPlaylistId")`.

- **AND-09** `widget/NowPlayingWidgetProvider.kt` — `onUpdate()` rendered only the cached snapshot; now calls `NowPlayingController.fetchAndStore()` first (already on background thread).

- **ANEW-10** `DevicesScreen.kt`, `AutomationScreen.kt` — merge/rename/delete/identify/test/automation-delete were fire-and-forget; now `runCatching` with errors surfaced to existing error/message states (`RoomsScreen`/`Dashboard` were already wrapped).
- **ANEW-13** *(found while reconciling backend tests — see SNEW-13)* `ApiDtos.kt` + all Now Playing consumers — the server now returns recently-**stopped** rows for resume, but no client could distinguish them from playing rows. ## Server Backend (`server.py`, `scripts/sync_plex_playlists.py`, `plex_client.py`, `catalog_cache.py`)

### P1 — fixed
- **SNEW-01** — **Lock-order deadlock**: `_store_queue`/`_set_queue_stop` took `_QUEUES_LOCK` → flock while `_load_queues`/`_save_queues` took flock → `_QUEUES_LOCK`. Ordering unified: `_QUEUES_LOCK` (RLock) always outermost, file lock innermost.

### Automations / scheduler — fixed
- **SRV-01** — `lastFiredAt` is now recorded per attempted slot regardless of outcome; a failing automation no longer re-fires every 30 s for the rest of its minute (`lastRunStatus` still records ok/error).
- **SRV-02** — "Run now" sets the current minute's slot key, preventing a same-minute scheduled double-fire.
- **SRV-20** — scheduler re-checks `enabled` under `_AUTOMATIONS_LOCK` immediately before firing (disable in the gap is now honored).

### Alexa skill / playback — fixed
- **SRV-03** — `ShuffleArtistIntent` UI-playlist-token path now passes `shuffle=True` (was playing in order).
- **SRV-04 / SNEW-02** — `_np_skip_next()` no longer blindly wraps `(idx+1) % len`; honors `stopAt`/`stopAfterIdx`, wraps only when `loop`, otherwise stops cleanly (speech for voice, silent for PlaybackController).
- **SRV-13** — artist play/shuffle SQL no longer hard-filters `('.mp3','.m4a','.aac')`; new `_streamable_ext_sql()` derives extensions from `NATIVE_EXTS`/`TRANSCODE_EXTS` (+FLAC/ffmpeg support), so FLAC/OGG-heavy artists are playable when transcoding is on.
- **SRV-14** — play-playlist tokens are no longer burned before playback starts: `_consume_play_playlist_token` is now a peek; the token is deleted only when the response actually contains an `AudioPlayer.Play` directive.
- **SRV-18** — `PlaybackFailed` auto-advance now honors `stopAt`/`stopAfterIdx` (sleep timers survive stream failures).
- **SNEW-03** — `IgnoreSongIntent` advance now honors loop/stop limits too.
- **SNEW-04** — MSP `GetNextItem`/`GetPreviousItem` return `isQueueFinished: true` when `stopAt`/`stopAfterIdx` limits are hit.
- **SRV-19** — song-on-device play tokens (`_PLAY_FILE_TOKENS`) are now persisted to `play_file_tokens.json` (mirroring playlist tokens), surviving service restarts within their TTL.

### Now Playing state races — fixed
- **SRV-05** — `nowplaying_devices()` read→expire→write is now inside `_NP_LOCK`.
- **SRV-06** — `PlaybackFinished`/`PlaybackFailed`/`PlaybackStopped` read-modify-writes wrapped in `_NP_LOCK` (PlaybackStarted writes a fresh dict through the already-serialized `write_np_state`).
- **SRV-16** — device-merge NP migration wrapped in `_NP_LOCK`.
- **SNEW-07** — `_clear_nowplaying_on_boot()` RMW wrapped in `_NP_LOCK`.
- **SNEW-13** — **API contract gap** (root cause of 3 failing tests): an uncommitted change keeps recently-stopped rows (<10 min) in `/api/nowplaying_devices` for widget resume, but rows carried no flag, so every client rendered them as actively playing. Added `'stopped': true` to idle rows and sort stopped rows last; web + Android updated (see WNEW-31 / ANEW-13); the 3 regression tests updated to assert the new contract (row may appear, must be `stopped` and never `paused`/playing). Full suite green.

### Playlist XML integrity — fixed
- **SRV-07** — `_msp_playlist_by_id()` now parses `ServerPlaylists.xml` under `playlist_xml_lock(shared=True)`.
- **SRV-08** — `summary()` XML fallback parse now takes the shared lock (sidecar-index fast path already avoided most parses).
- **SRV-09** — Plex sync writes XML via temp file + `os.replace` (atomic).
- **SRV-10 / SNEW-11** — `_save_playlists_tree()` now uses `_atomic_xml_write`, and `_atomic_xml_write` standardized on `utf-8` (was locale-dependent `encoding='unicode'`).
- **SRV-11** — sync now writes the XML *before* `save_state()`; a crash can no longer leave the cache ahead of the files (changes silently never re-syncing).
- **SRV-12** — playlists dropping below `--min-tracks` now have their stale `.m3u` deleted (entry prunes via the existing plex-row rebuild).
- **SNEW-10** — `catalog_cache.rebuild_playlists_index_from_xml()` takes the shared XML lock; the sync script's call moved outside its exclusive-lock block to avoid same-process flock self-deadlock.

### Devices & security — fixed
- **SRV-15** — device-merge queue "migration" checked `source_id in queues`, but queue keys are random queue IDs (and queue entries store no deviceId) — provably dead code; removed with an explanatory comment.
- **SRV-17** — `/api/artwork_url` now validates `path` with `_path_under_root(path, MUSIC_ROOT)` (400 otherwise); no more signed URLs for files outside the library.

### Not a bug (verified)
- **SNEW-05 / SNEW-06** — `POST /api/config` / `POST /api/settings` "unauthenticated": `before_request` enforces auth on all `/api/` paths whenever a WebPassword is configured (and always for tunnel/external requests). With no password set there are no credentials to check — intended open-LAN mode.
- **SNEW-08** — `plex_client.track_ratingkey_for_path()` searches by basename but only returns on an **exact full-path** match; duplicate filenames cannot mis-resolve.

### Deferred (documented, intentionally unchanged)
- **SNEW-09** — scheduler uses naive local `datetime.now()`; local-time semantics are intended for a home server (DST shifts a slot by an hour twice a year).
- **SNEW-12** — test fixtures only cover `.mp3` tracks; transcode-format coverage for artist/album intents would be a worthwhile test addition (not a product bug).

# Pass 3 — 2026-06-12 full runtime sweep (every page, button, API, workflow)

A live exercise of the whole surface rather than code reading: an isolated instance of the current code (temp state dir, production data untouched) was driven through **184 runtime checks** covering every Flask route (all 86) and every UI workflow end-to-end — static pages/assets, dashboard, library (artists/albums/songs/genres/search), playlist create→detail→edit→sort→remove-track→rename→merge→delete, smart playlist create→refresh→update→delete, AI-playlist error paths, device register→rename→merge→dismiss→delete, device groups CRUD, automations create→update→run-now→delete (+validation rejects), favorites/ignored/selected add+remove, now-playing sleep/control/volume validation, settings & config round-trips, cache clear, stream/artwork traversal guards, 24 Alexa intents (all returned valid envelopes), CanFulfillIntentRequest, MSP auth rejects, and OAuth error paths.

Plus two static cross-checks: all **59 API paths referenced by `app.js`** exist server-side with matching HTTP methods, all **50 `onclick` handlers** resolve to defined functions, all boot-critical DOM ids exist in `index.html`; all **70 Android Retrofit endpoints** match Flask routes and methods.

**Result: 184/184 runtime checks pass** after fixing 2 defects the sweep exposed:

- **RT3-01 (P1)** `server.py` — **Six endpoints permanently 401 on open-LAN installs** (no WebPassword / mobile token configured): `POST /api/devices/identify`, `GET /api/devices/identify/status`, `POST /api/devices/test`, `POST /api/alexa_remote/login/start`, `POST /api/alexa_remote/login/stop`, `POST /api/clients/report` used a strict `_basic_auth_ok() or _mobile_api_token_ok()` check that can never pass when no credentials exist to present. On an open install the Devices page "Identify all" / "Play test clip" buttons and the Settings Alexa-login flow were dead, and mobile client reporting failed. Now use the same `_console_auth_required() and not (...)` pattern as the rest of the API (external/tunnel requests remain gated by `before_request`; installs with a password still require it).
- **RT3-02 (P3)** `server.py` `/api/nowplaying/sleep` — malformed `minutes`/`songs` returned `409 nothing_playing` instead of `400 invalid minutes/songs` when nothing was playing (validation ran after the queue lookup). Input is now validated first.

Sweep findings that were **not** bugs (verified): automation `days` must be int indices 0–6 (both web and Android send ints — names were a test-harness error); automation `PUT` requires the full object (both clients send it); identify/test validate before touching the live Alexa API.
